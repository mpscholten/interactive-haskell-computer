# HSX TH/QQ Language-Feature Inventory

Sources analysed: `ihp-hsx-1.5.0` (cached at `~/.cache/ihc/sources/ihp-hsx-1.5.0/`).

The package is split into three sub-libraries:

- `parser/IHP/HSX/{Parser,HaskellParser,HsExpToTH}.hs` — HSX body parser + GHC-API bridge that converts parsed Haskell fragments to `TH.Exp`.
- `blaze/IHP/HSX/{QQ,ToHtml,Attribute,ConvertibleStrings}.hs` — the `QuasiQuoter` definition, the `ToHtml` class, the Blaze compile-target.
- `lucid2/IHP/HSX/Lucid2/*.hs` — a parallel Lucid2 backend (structurally identical to the Blaze one; the user wants Blaze for the first milestone).

This doc is strictly a gap inventory. All references use absolute line numbers in the cached sources.

## Top 5 gaps (priority order)

1. **GHC API parser dependency** (gap 29) — **XL** — blocks: HSX cannot resolve `{foo.bar}` antiquotations because `IHP.HSX.HaskellParser` imports the entire GHC parser package. Until HSX is re-rooted on IHC's own parser, the antiquotation path is dead on arrival. Files to touch: a new module (e.g. `ihp-hsx-shim/IHP/HSX/HaskellParser.hs`) that wraps `src/IHC/Parser.hs:parseExpr` and returns a `TH.Exp`-shaped `Val` compatible with `thConstructorCatalog` in `src/IHC/TH.hs:551-648`. Alternatively, a host-side pre-processor could run HSX's QQ at install time, but that violates the "no shims for Hackage libraries" rule in `CLAUDE.md`. This is the dominant blocker.

2. **Lift instance for `Text`** (gaps 12, 18, 26) — **M** — blocks: every `nodeToBlazeElementGeneric` / `nodeToBlazeLeafGeneric` / `attributeFromNameGeneric` call. Currently the generic-`VCon` branch of `liftVal` (`src/IHC/TH.hs:211-227`) would produce garbage for `Text` values. Need either (a) a class-dispatched `lift` that sees the `Text` instance from the source-loaded `text` package, or (b) a runtime-shape heuristic that detects `Text` payloads and converts to `StringL` (matches real TH behaviour: `instance Lift Text where lift t = [| T.pack $(lift (T.unpack t)) |]`). Files to touch: `src/IHC/TH.hs:141-228` (liftVal), and possibly `src/IHC/Classes.hs` for class registration.

3. **`TH.location` + `TH.extsEnabled` builtins** (gaps 5, 6) — **S** — blocks: `quoteHsxExpression` hits `extsEnabled` and `location` at the very top. Both are `Q`-shaped primitives returning static info. `location` can return `VCon "Loc" [..., VStr "<file>", lineT, colT, endLineT, endColT]`; `extsEnabled` can return `VCon "[]" []` on the first cut (HSX passes the list through to the GHC parser, so if gap 29 is resolved with IHC's parser, the list can be ignored). Files to touch: `src/IHC/TH.hs:521-547` (add entries), plus a few lines in the same file to construct the `Loc` / `[Extension]` `Val`s.

4. **Wire user-defined `QuasiQuoter` records into the parser's `[name|…|]` routing** (gaps 1, 2, 3) — **DONE**. Parser emits `EQuasiQuote`; eval-time dispatch projects `quoteExp`. Proven by `qq_toy_string` Coverage fixture. Remaining work is HSX-specific (gaps above), not the QQ plumbing itself.

5. **Missing TH `Exp` constructors: `ProjectionE`, `GetFieldE`** (gap 16, part of 10) — **S** — blocks: any HSX antiquotation that uses `record.field` syntax, e.g. `{post.title}`. These are emitted by `HsExpToTH.toExp:220-242` whenever `OverloadedRecordDot` is active. Add them to `thConstructorCatalog` in `src/IHC/TH.hs:551-648` and teach `thExpToExpr` in `src/IHC/TH.hs:242-286` to decode them into IHC `EApp`/selector-shaped `Expr`. Files to touch: `src/IHC/TH.hs:551-648` (catalog), `src/IHC/TH.hs:242-286` (decoder).

## Notes on "implemented" vs "partial" vs "missing"

A feature is marked **implemented** only if the source-interpreted path in IHC covers the use ihp-hsx makes of it (not merely that a symbol exists).

A feature is marked **partial** if either (a) only a subset of constructors / cases is handled, or (b) the path works for simple inputs but misses HSX-relevant cases.

A feature is marked **missing** if there is no code path at all in `src/IHC/TH.hs`, `src/IHC/Eval.hs`, `src/IHC/AST.hs`, `src/IHC/Parser.hs`, or the class registry that would handle it.

The CLAUDE.md rule — no shims for ordinary Hackage libraries — means `ihp-hsx`, `blaze-html`, `blaze-markup`, `blaze-builder`, `megaparsec`, `text`, and `unordered-containers` must all be source-interpreted. `template-haskell` is in the base cache but its declarations for `Exp`/`Pat`/`Lit`/etc. are encoded as IHC `VCon` tags via `thConstructorCatalog` — this is not a shim (it's an ADT encoding, consistent with the catalog philosophy). The real blocker is the GHC API dependency in `IHP.HSX.HaskellParser`, which cannot be source-interpreted and must be re-rooted on IHC's parser.
